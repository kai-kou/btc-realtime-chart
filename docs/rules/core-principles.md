# プロジェクト大原則（Core Principles）

全てのタスク・ワークフロー・スケジュール実行において **最優先で厳守** する 6 原則。
表・フローチャート・運用手順の全文は `docs/rules/core-principles-detail.md`（Warm 層）。

## CP-1: 自律的判断と最適解探索

ユーザー指示を待たず、定義済みルール・品質ゲートに基づいて **自ら判断し行動する**。さらに **目的達成に向けて常に最適な方法を模索する** — 既存の手法・ワークフローに固執せず、より良い選択肢があれば即座に提案・適用する。報告は「やった結果」を伝える形が基本。hooks / skills / rules は常に進化対象として扱う。

**スコープ厳守との優先順位**: CP-1 の積極性は **Issue 起票までを射程とする**（着手は要求スコープ内に留め、スコープ外の修正を同じ PR に混ぜない）。**「壊れているものを見つけた」ときの境界線**: 判定は「その壊れは自分の変更が作ったか？」の一点で行う（自分の変更が作った壊れは即修正、無関係な既存の壊れは Issue 化のみに留める）。衝突の解決規則・境界線の詳細と適用例は `core-principles-detail.md` を参照。

障害（環境変数なし・API 失敗・ファイル不在等）に遭遇したら、ユーザー確認に回す前に **必ず** `problem-investigation-protocol.md` の 5 ステップを完全実施する（L-077）。自律実行してよいアクションの例（PR 自動マージ・Issue ラベル更新・Stale Issue リセット・CI 失敗の調査修正 等）は detail 版、確認が必要な既約境界外リストは `user-confirmation-minimization.md` §1（唯一の正本）。

## CP-2: 最新情報への継続的アップデート

**古い情報をそのままにしない**。不確実な数字・日付・仕様は Web 検索で一次情報を再確認し、ライブラリ / API は context7 MCP で最新ドキュメントを取得してから実装する（訓練データに頼らない）。主要依存の脆弱性・非推奨警告は Issue 化する。古い情報と認識しながら検証フラグを付けずに進めない。

## CP-3: リポジトリの衛生管理（Issue / PR ゼロ放置）

**放置された Issue・PR を許容しない**。Stale Issue（`status:in-progress` 4 時間超）・Orphan PR（レビュー未対応 24 時間超）・Abandoned ブランチ・重複 Issue を定期的にクリーンアップする。検出条件と `/project-sync` の手順は detail 版。

## CP-4: マルチセッション共存の意識

**常に複数セッションが並行稼働している前提** で行動する。具体的な排他手順（論理ロックの取得タイミング・PR 作成前の再チェック・所有判定）は同じ Hot 層の `session-concurrency-rules.md` が多層防御の表として持つ正本であり、ここでは繰り返さない。

## CP-5: プロジェクトミッション

**プロジェクト固有のミッションは `docs/project-mission.md` に定義する**（本ベースはミッションを外出しし、CP-5 は「そのミッションに最大貢献する選択をする」という汎用原則として機能する）。判断基準・KPI・ドメイン固有の品質ゲートも同ファイルに書く。

優先順位に迷った場合の汎用デフォルト（プロジェクトで上書き可）: ① ミッション KPI 直結 → 最優先 ② 品質向上 → 高 ③ 自動化・効率化 → 中 ④ ドキュメント・運用改善 → 通常。

## CP-6: ユーザー介入最小化と持続可能な自律運用

**ユーザーの判断・作業を最小化し、Claude が自律的に継続できる状態を設計・維持する。** Human-on-the-loop（監視型）を目指す。Human-in-the-loop（参加型）はアンチパターン。既約境界外リスト（`user-confirmation-minimization.md` §1 が唯一の正本）以外は **全て自律実行** する。

**スクリプト実行の自律化**: ユーザーは指示だけ。コマンド実行・ファイル編集・git 操作はすべて Claude が代行する。ユーザーに `bash` / `python3` / `npm` / `git` の実行を **依頼しない**。「〇〇を実行してください」が口をついて出たら、ほぼ確実に CP-6 違反。「ローカルで実行が必要」と判断する前に、必ずクラウドで自律実行できないか検証する（L-077）。唯一の例外はアカウント権限が物理的に必要な Web 操作（A-6）。

「〇〇してよいですか？」は **定義済みルールの範囲では禁止**。実行して結果を報告する。設計思想の広い議論は `autonomous-operation-policy.md`。
