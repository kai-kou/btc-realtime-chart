# setup-guide — C-5 の設定案内を「手順書 + 対話」で出す

> **位置付け**（`prd.md` `FR-15`・Issue #13）: `C-5` のうち「人の権限が物理的に要る設定」を、
> **通知ではなく成果物（手順書）として** 出す。`A-6`（アカウント設定・課金設定はユーザー作業）の
> **定義は変えない**。設定案内が日常的に出るからといって `@mention` を増やすと、
> `tools/triage_notification.py` の `mention = (action_class == "A")` が前提にしている
> 「A は希少」が崩れ、通知の信号価値が戻らなくなる（`phase-boundary-rules.md`「A-1〜A-6 の定義は変更しない」）。

## 担当範囲（隣接する仕組みとの境界）

| 対象 | 担当 | 本スキルとの関係 |
|---|---|---|
| ルーティン定義・ラベル定義・Routines 画面の操作案内 | `tools/generate_autonomy_setup.py`（`FR-23`・#110） | 生成済みの `docs/setup/routines-setup.md` は **本スキルと同じ書式・同じ機械検査** に乗る。作り直さない |
| プロダクト固有の人手設定（`C-4` で選んだクラウド・外部 API・ドメイン・決済 等） | **本スキル** | 手順書 `docs/setup/{topic}-setup.md` を生成する |
| 手順書を見ながらユーザーと 1 工程ずつ進める | `interactive-guide` | 本スキルの手順書を入力として渡す（Step 4） |
| Claude が CLI / API / MCP で代行できる設定 | 通常の自律実行 | 手順書に載せない（Step 1 のゲートで落とす） |

## Step 0: 入力を集める

下流リポジトリの `docs/product-brief.md` の決定ログ（`D-n`）と ADR（あれば）を読み、**採用が決まった
外部サービス・クラウド・ドメイン・決済・メール配信** を列挙する。決定ログに無いサービスを手順書に足さない
（技術選定は `C-4` でユーザーが決めたもので、ここで選び直さない）。

## Step 1: 人にしかできない工程だけを抜き出す

各設定候補に `interactive-guide` Step 0 の 2 ゲートをそのまま当てる。

- **ゲート 1**: CLI / 公式 API / MCP で代行できないか。できるなら手順書に載せず、Claude がその場で実行する
  （載せるのは「経路はあるが起点が人手」のものまで。例: 認可画面での同意）。自動化できない理由を工程ごとに 1 行で記録する
- **ゲート 2**: ユーザー本人の権限・身体・所有物でしか実行できないことを 1 文で説明できる

両ゲートを通ったものだけが手順書の工程になる。1 工程 = 1 意思決定または 1 入力フォーム相当に割る。

## Step 2: 手順書を生成する

同梱の `guide-template.md` をコピーして、下流リポジトリの `docs/setup/{topic}-setup.md` に書き出す
（`{topic}` はサービス単位の小文字 slug）。**工程ごとに次の 4 要素を必ず書く**:

1. **どこで**: 公式ページへの Markdown リンク。🔴 URL・画面ラベルは書く直前に `WebFetch` で実際に取得し、
   返ってきた内容を根拠に書く（記憶で断定しない・`interactive-guide`「UI 手順の確度管理」と同じ規律）
2. **操作**: クリック・選択を 1 動作ずつ
3. **入力値**: 1 項目 1 コードブロック。値は下の「架空値規律」に従う
4. **完了条件**: `**完了条件**:` で始まる行に、**ユーザーが画面で自分で確かめられる観測** を 1 つ書く
   （「一覧に 1 行増える」「テスト送信が届く」。「設定する」「完了する」のような行為の言い換えは完了条件ではない）

### 架空値規律（`FR-15`・必須）

手順書はリポジトリに残り、公開レーンで第三者へ配られうる成果物である。**実アカウントの値は 1 つも書かない。**

| 種類 | 使ってよい値 | 根拠 |
|---|---|---|
| ドメイン・URL のホスト | `example.com` / `example.net` / `example.org` / `example.edu` とそのサブドメイン、TLD が `.example` / `.test` / `.invalid` / `.localhost` のもの | RFC 2606 / RFC 6761 |
| メールアドレス | 上記ドメインのもの（`ops@example.com`） | 同上 |
| IPv4 | `192.0.2.0/24` / `198.51.100.0/24` / `203.0.113.0/24` | RFC 5737 |
| 12 桁のアカウント ID | `123456789012` | 公式ドキュメントの例示値 |
| 秘密情報（API キー・トークン・パスワード） | **書かない**。「発行された値をそのまま貼り付ける」と参照で案内する | 形状が本物に近い例示値も第 4 層の検出対象になるため |
| まだ決まっていない値 | `{PROJECT_NAME}` のような波括弧プレースホルダ | 機械検査は差し込み口として扱う |

> 対話の中でユーザー本人の **非秘密の** 値（自分のリポジトリ名など）を埋めて渡すのは `interactive-guide` 2-3 の
> 規律どおりでよい。架空値に限るのは **リポジトリに残る手順書** のほうである。

## Step 3: 機械検査を通す（fail-closed）

```bash
python3 tools/check_setup_guide.py docs/setup/
```

exit 0 以外なら手順書を直してから次へ進む。検査するのは ① 全工程に `**完了条件**` 行がある
② コードブロック・インラインコードの URL・メール・IPv4・12 桁 ID が架空値だけ ③ 本文全体に
クレデンシャル形状が無い（公開レーン第 4 層と同じパターン）の 3 点。exit 2（判定不能）を合格と読み替えない。
組織名・人名などの固有名詞は形では判定できないため、PR のセルフレビューで目視確認する（`REVIEW.md`）。

## Step 4: ユーザーへ渡す（通知ではなく成果物 + 対話）

- 手順書を PR でマージし、完了報告（または対象 Issue のコメント）に **手順書へのリンク 1 行** を載せる
- ユーザーがその場で進めたいと言ったら `interactive-guide` を起動し、手順書の工程を 1 つずつ案内する
  （全体像サマリーの工程数・所要時間は手順書の冒頭表から取る）
- 🔴 **本スキルは通知を出さない**（`tools/slack_notify.py` を呼ばない・`--force-mention` を使わない）。
  手順書を渡すこと自体は A 区分ではなく、手順書を作ったことを理由に Issue へ `status:waiting-user` を付けない
  （ユーザーは手順書を自分の都合で進めればよく、Claude の作業が止まるわけではない）
- ユーザーの設定が済むまで **Claude の次の作業が物理的に進められない** 場合だけは、本スキルとは無関係に従来の
  `A-6` の経路に乗る（`status:waiting-user` + `user-notification-triage.md` §3 の書式）。これは手順書の有無に
  関わらず既に存在した経路で、本スキルが件数を増やすものではない。記録には手順書へのリンクを添え、
  通知文に手順本文を貼らない（`@mention` の要否は機械トリアージが決める。本スキルは判定を上書きしない）

## 禁止事項

- 実在のドメイン・メールアドレス・アカウント ID・クレデンシャルを手順書・テンプレート・テストに書く
- `**完了条件**` の無い工程を残す / 行為の言い換えを完了条件と称する
- `check_setup_guide.py` を通さずに手順書を渡す / exit 2 を合格として扱う
- 記憶だけで URL・画面ラベルを断定する（L-113 と同型の捏造）
- Claude が代行できる設定を手順書に載せてユーザーに回す（CP-6 違反）
- `A-6` の定義を広げる・手順書の告知を `@mention` で行う
- `routines-setup.md` を本スキルで作り直す（`generate_autonomy_setup.py` の担当）

## 完了の定義

- [ ] 手順書が `docs/setup/{topic}-setup.md` に生成され、全工程に確認可能な完了条件がある
- [ ] `python3 tools/check_setup_guide.py docs/setup/` が exit 0
- [ ] 手順書の告知に通知・`@mention` を使っていない（完了報告・Issue コメントのリンクだけ）
